# 旅行规划 Multi-Agent 系统设计

**日期**: 2026-02-26

## 1. 项目概述

**项目名称**: Travel Planner - 智能旅行助手

**核心目标**: 通过多 Agent 协作，实现从需求分析到行程规划的完整闭环，打造可日常使用的智能旅行规划产品。

**学习目标**:
- CrewAI 框架实战
- 多 API 集成与编排
- 异步任务处理与并发控制
- 分布式 Agent 系统设计

---

## 2. 技术选型

### 框架与工具

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| **Agent 框架** | CrewAI | 上手简单，角色定义清晰，适合展示协作能力 |
| **LLM** | OpenAI GPT-4 / Claude | 主流选择 |
| **搜索工具** | Tavily / DuckDuckGo | 免费获取旅行信息 |
| **后端** | FastAPI | 快、现代化、易部署 |
| **前端** | React | 主流生态好，易扩展 |
| **部署** | Render / Railway | Serverless 友好 |

### 数据源策略

- **初期**: 使用搜索工具（Tavily/DuckDuckGo）获取公开信息
- **后期**: 有用户量后考虑接入国内API（携程/飞猪）

## 4. Agent 角色设计

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| **旅行顾问** | 需求澄清、用户偏好挖掘 | 用户模糊需求 | 清晰的需求清单 |
| **搜索代理** | 调用搜索工具获取信息 | 查询关键词 | 搜索结果摘要 |
| **行程规划师** | 整合信息，生成行程安排 | 搜索结果+偏好 | 每日行程计划 |
| **预算分析师** | 计算费用、优化预算 | 行程安排 | 费用明细+优化建议 |
| **天气/应急代理** | 天气预警、延误处理方案 | 目的地+日期 | 应急方案 |
| **旅行日记生成器** | 行程结束后生成回忆录 | 行程数据 | 旅行日记 |

### 协作流程

```
用户需求 → 旅行顾问(澄清) → 搜索代理(获取信息)
    → 行程规划师(生成计划) → 预算分析师(费用)
    → 天气代理(风险评估) → 返回用户
```

## 5. API 设计

### 后端 API 端点

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | `/api/trips/plan` | 创建旅行计划 |
| GET | `/api/trips/{id}` | 获取旅行计划详情 |
| POST | `/api/trips/{id}/optimize` | 优化行程 |
| GET | `/api/trips` | 获取用户所有旅行计划 |

### 请求示例

```json
POST /api/trips/plan
{
  "destination": "日本东京",
  "duration": 5,
  "budget": 10000,
  "travelers": 2,
  "preferences": ["美食", "购物", "文化"]
}
```

## 6. 前端设计

### 页面结构

1. **首页** - 输入旅行需求
2. **规划中** - 展示 Agent 协作进度
3. **行程详情** - 展示完整行程卡片
4. **我的旅行** - 历史旅行记录

### 交互流程

```
首页 → 输入需求 → 调用后端API → WebSocket推送进度
    → 展示结果 → 用户可调整 → 确认行程
```

---

## 7. 部署方案

### Render 部署配置

- **后端**: FastAPI 服务，512MB 内存
- **前端**: 静态文件托管
- **超时处理**: Agent 任务使用异步队列，结果通过 WebSocket 推送
